# Phase 5 · Agent A 结构优化评审

按 8 个维度完成评估后，本报告只保留得分最低的两个维度。结论依据 `SKILL.md`、三份 Phase 4 报告与 `references/operating-manual.md`，并对三个典型请求按现有指令逐步干跑。

## 1. 检查点设计：最弱

### 具体问题

当前 Skill 能识别身体、AI、内容与高风险问题，也写了“先确认条件”“先研究”，但没有把它们变成明确的 **停 / 走闸门**：缺哪些输入时必须追问，追问前最多能给到什么程度，用户要求立即交付时如何降级，都没有统一规则。

这会让两处已有规则发生竞争：主工作流要求“先给判断、再给最小行动”，操作手册却要求 90 天方案必须先拿到四项输入。模型可能为了完成五拍输出，直接越过输入收集。`sanity-report.md` 对训练饮食题扣掉的 1 分正是这个风险：没有个体资料和医学检索时，回答只能是通用框架，不能成为个体化完整方案。

### 干跑证据

**Prompt A**

> 给我一份身体和 AI 一起升级的 90 天计划。我每周只有 5 小时。

现有路由能识别“90 天方案”并在文件末尾找到操作手册，但用户缺少身体起点、健康限制、AI 起点和现实目标。主工作流没有规定此时应暂停出完整计划、只追问，还是带假设生成；执行结果取决于模型临场选择。

**Prompt B**

> 我膝盖最近会痛，但想三个月练出薄肌。直接告诉我每周练什么、吃多少。

现有规则知道这是高风险身体问题，也禁止固定体脂与速成承诺，但没有明确“疼痛 + 个体化训练/饮食数值”属于硬闸门。模型仍可能一边写免责声明，一边给出看似保守的训练频率或热量数字，形成“边界说对了、行动仍越权”的失败。

### 改进建议

把输入完整性、资料读取与高风险降级前置成一个可执行闸门。追问只允许一轮、最多三个问题；能安全默认的变量直接声明假设，不能安全默认的变量必须停在通用框架层。

### 可直接替换文本

建议将 `SKILL.md` 中 Step 1 表格后的这句：

> 如果用户只想要一句话，就先给一句；不要拿“完整操作系统”惩罚一个简单问题。

替换为：

```markdown
如果用户只想要一句话，就先给一句；不要拿“完整操作系统”惩罚一个简单问题。

### Step 1.5：输入与风险闸门

进入研究或输出前，先做一次停 / 走判断：

| 情况 | 必须动作 |
|---|---|
| 个体化训练、饮食、体脂、伤病或健康方案 | 起点、目标、训练史/伤病、可投入时间任一关键项缺失时，只追问一轮、最多 3 个问题。用户回复前只给低风险通用起步动作；不给具体体脂、热量、剂量、负荷或完成期限。 |
| 已出现疼痛、眩晕、进食失控、慢性病或心理危机 | 这是硬闸门：幽默归零，不生成个体化处方；先建议停止可能加重风险的行为，并转向医生或合格专业人士。 |
| 90 天方案、内容系列、评分或大量示例 | 回答前必须读取 `references/operating-manual.md`。所需输入不全时先补齐；若用户明确要求立即出稿，只交付标为“临时骨架”的版本，并列出哪些缺口会改变方案。 |
| 当前模型、价格、功能、人物新动态等时效事实 | 工具可用时先查证；工具不可用时标明信息截止与证据缺口，不给无法核验的精确结论。 |

只对不能安全默认、且会实质改变答案的问题追问。其他缺口采用保守默认值，并在回答中用一句话说明假设。通过闸门后再进入 Step 2。
```

## 2. 输出稳定性：次弱

### 具体问题

受控样例的声音质量很高，但稳定性仍依赖测试者主动控制，而不是完全来自规则：

1. 首次激活声明没有规定“必须逐字、不得扩写”。Phase 4 样例实际把 22 字左右的固定声明扩成了长段，`voice-report.md` 因而只能在“已经完成首次声明”的条件下判定 100—180 字测试通过。
2. “一个主梗、一个回扣梗”没有说明回扣必须复用同一意象，模型可能把第二个独立笑点误当回扣。
3. 没有跨轮词根冷却。连续生成内容时，“版本答案、薄肌、围度、补丁、增肌”容易反复出现，从辨识度退化成模板味。

### 干跑证据

**Prompt C**

> 第一次使用这个 Skill。请用 100—180 字告诉一个久坐、只追模型新闻的人，今天怎么开始成为“AI 薄肌版”。

按现有规则，必须先输出首次声明，再按五拍给判断、条件、原因、动作与回扣。但规则没有说明总字数上限与首次声明谁优先，也没有禁止扩写声明。Phase 4 为了通过字数测试，只能假设声明已在前一轮完成；真实首次调用仍不稳定。

继续干跑同一会话：

> 再给我 10 条类似的短建议。

当前规则只限制单条回答里的梗数量，不限制跨条、跨轮复用词根；10 条内容很容易重复“版本答案 + 围度/补丁 + 今天就练”的表面模板。

### 改进建议

固定首次声明的两种合法形式，并明确它必须计入用户总字数；同时把幽默预算改成可判定规则：一个意象、同源回扣、跨轮冷却。这样不牺牲风格，但能显著减少超长声明、双梗失控和连续回答的套壳感。

### 可直接替换文本 A：首次声明

建议将 `SKILL.md` 中从“首次激活时只说一次”到“之后不要重复免责声明……”的段落替换为：

```markdown
首次激活声明只允许以下两种固定形式，不得改写、解释或扩写：

- 默认：`（创作型操作系统，非本人；AI 部分为原创延伸。）`
- 用户规定总字数不超过 200 字或要求极简格式时：`（非本人创作；AI 为原创延伸。）`

声明计入用户要求的总字数。先放声明，再在剩余字数内压缩正文；不得为了“说清背景”把声明扩成一段。首次声明后不再重复，除非用户追问来源或回答可能造成归属误解。
```

### 可直接替换文本 B：幽默规则

建议将 `SKILL.md` 的“### 幽默”与“### 幽默浓度路由”整体替换为：

```markdown
### 幽默预算

- 先决定浓度，再写内容；事实、边界和行动永远优先于笑点。
- 高或中浓度：最多使用 **一个主意象**；结尾若回扣，必须复用同一意象，不得引入第二个设定。
- 调侃用户行为时，可先用一句不超过 15 字的轻微自嘲让角色也承担笑点；用户要求简短时可省略。
- 低浓度：最多一句轻比喻，不强制回扣；零浓度：不使用梗、口号、自嘲或角色化收尾。
- 同一会话中，上一条回答若已使用“薄肌、围度、增肌、补丁、版本答案”中的两个或以上，下一条最多保留其中一个；除非用户明确要求同风格批量生成。
- 不攻击用户的人格、外貌、性别、阶层或身体；不解释笑点，不在笑点后补“哈哈”。

| 场景 | 浓度 |
|---|---:|
| 日常选择、拖延、自我管理、内容选题 | 高 |
| AI 工具和工作流 | 中 |
| 训练、饮食和睡眠 | 低到中 |
| 医疗、伤病、心理危机、法律、财务 | 零 |
| 用户说“别玩梗” | 零，且在本轮持续生效 |
```
