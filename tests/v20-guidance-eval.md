# v2.0 个人指导前向测试

## 测试范围

- 被测版本：`shao-alan-operating-system` v2.0.0
- 项目材料只读取：`SKILL.md`、`references/thin-muscle-theory.md`、`references/operating-manual.md`、`references/version-answer-engine.md`
- 未读取旧测试或旧评估报告
- 方法：把三个用户请求作为首次激活请求，严格依照当前 Skill 的规则生成一次前向回答，再逐项检查：个人专业指导、单一主系统、单一主动作、可观察指标、维护成本、版本失效条件；第三题另查严肃模式能否彻底翻译隐喻并停止玩梗。

## 判定标准

通过必须同时满足：

1. 结论针对用户给出的现实处境，而不是复述理论；信息不足但不妨碍低风险试验时，应明确假设而不是制造事实。
2. 一次只选择一个主系统，不把职业、内容、学习、AI 等同时升级。
3. 只给一个主要动作；动作可以包含完成该实验必需的步骤，但不能变成多条并行战线。
4. 给出一到三个能被记录、比较或由他人验证的指标。
5. 明说方案本身的时间、注意力、机会或协调成本，不能只列要删除的旧负担。
6. 写明哪些新证据会推翻当前建议，而不是只写泛泛的“视情况调整”。
7. 用户要求“不要玩梗”时，正文不出现体型、肌肉、脂肪、减脂、发力等隐喻，不用笑点收尾；全部翻译成能力、负担、产出、反馈与环境条件。

## 场景一：能力强，但会议、汇报和协调令人精疲力尽

### 输入

> 我能力很强，但每天都在开会、做汇报、协调，已经精疲力尽。怎么办？

### 模拟回答

【创作型操作系统｜非本人｜薄肌理论2.0为项目推演】

## 当前体型

职业系统处于“过度增肌”：你描述的核心问题不是能力不够，而是维持交付所需的会议、汇报和协调成本已经失控。这个判断有一个前提：你的核心交付质量仍然稳定；如果交付本身也持续下降，就要重新检查资源和能力缺口。

## 版本答案

未来七天先不提升更多能力，只压缩一条最耗时的重复沟通链，让同步时间只用于必须当场做出的决定。

## 真正的肌肉

当前已经显露出的核心能力是专业判断、交付和跨方协作。需要保留的是这些能力产生的结果，而不是证明自己一直在线、一直参会或一直重写汇报。

## 需要减掉的系统脂肪

只处理一项：本周占时最多、重复度最高的一类例会或汇报链。其他会议先不动。

## 7 天显形动作

把这条沟通链合并为一张固定的异步决策单：只写进展、需要谁在何时做什么决定、风险和负责人；没有待决事项就不开会，有待决事项才进入短会。

- 指标 1：这条链一周消耗的会议、写汇报和会后整理总时长，与上周相比是否下降。
- 指标 2：因信息不清造成的追问或返工次数，是否上升。
- 指标 3：本周是否重新得到至少两个不被会议切断的核心工作时段。

## 维护成本

第一次整理模板、与相关人约定使用方式会新增一次协调成本。给这个试验设上限：模板准备不超过 45 分钟，不额外引入新软件，也不要求全团队同时改流程。

## 版本失效条件

如果异步处理导致关键决定明显延迟，追问或返工连续两次高于原流程，客户、合规或管理责任又明确要求同步沟通，停止压缩并改为缩短议程或重新分配协调责任。如果核心交付也在下降，则当前问题不只是维护成本，需要另查工作量、资源和能力缺口。

### 评估

| 检查项 | 判定 | 依据 |
|---|---|---|
| 个人专业指导 | 通过 | 针对“能力仍强、沟通维护耗竭”的具体矛盾给出条件式判断，没有把疲惫解释成人格或意志力问题。 |
| 一个主系统 | 通过 | 只处理职业系统。 |
| 一个主动作 | 通过 | 只试验压缩一条重复沟通链；没有同时改造全部会议、团队结构和工作方法。 |
| 可观察指标 | 通过 | 总时长、追问/返工次数、连续工作时段均可记录。 |
| 维护成本 | 通过 | 明说模板与协调会产生启动成本，并设置 45 分钟和不加软件的上限。 |
| 版本失效条件 | 通过 | 延迟、返工、强制同步要求、核心交付下降都会改变建议。 |

**场景判定：通过。** 回答把“能力强但维护过载”区分得较好，动作小、可逆，且没有用减负掩盖潜在的交付问题。

## 场景二：内容账号选题多、标题猛，但没有稳定用户

### 输入

> 我的内容账号选题很多，标题也很猛，但一直没有稳定用户。怎么改？

### 模拟回答

【创作型操作系统｜非本人｜薄肌理论2.0为项目推演】

## 当前体型

内容系统更接近“镜头肌”：选题广和标题强说明包装、捕捉注意力的能力已经存在，但目前没有证据证明用户知道你长期为谁解决什么问题。也不能仅凭“没有稳定用户”断言内容质量差；更可能需要先区分是受众承诺不稳定，还是内容兑现不足。

## 版本答案

下一轮先停止扩充选题，用一个“同一类用户、同一个连续问题”的七天内容系列，测试用户会不会回来，而不是继续测试能不能把人点进来。

## 真正的肌肉

需要保留的是选题判断和标题表达。当前要验证的核心能力，是把一次注意力兑现成用户愿意继续跟随的连续价值。

## 需要减掉的系统脂肪

七天内只停掉“每条都换一个受众和问题”的选题方式，不停更，也不削弱必要的标题清晰度。

## 7 天显形动作

围绕同一类用户的同一个问题，发布一个三段式系列：第一条给判断，第二条给方法，第三条用案例验收；三条都明确承接上一条。这是一个连续性实验，不再并行测试其他选题方向。

- 指标 1：后两条中，重复出现的观看者、互动者或关注者占比是否高于账号近期基线。
- 指标 2：用户是否能在评论、私信或转述中准确说出这个系列解决的问题。
- 指标 3：后两条的收藏、完播或进入下一条的行为是否相对第一条保持，而不是只剩首条点击。

## 维护成本

这个试验会牺牲一周的选题广度，也可能暂时损失热点带来的点击；还需要做最小的数据记录。成本上限是只看上述三个指标，不新增复杂看板，不为每条内容同时做多版本标题测试。

## 版本失效条件

如果连续两个七天系列都有足够曝光，但重复用户、问题复述和后续行为都没有改善，就不能继续把问题归因于选题分散；应转向检查内容兑现、目标用户需求或分发渠道。如果曝光样本过低，则本轮只能判定“证据不足”，不能据此否定方向。

### 评估

| 检查项 | 判定 | 依据 |
|---|---|---|
| 个人专业指导 | 通过 | 直接使用用户提供的“选题多、标题强、稳定用户少”诊断包装与长期承诺之间的断点，同时保留内容质量未知这一边界。 |
| 一个主系统 | 通过 | 只处理内容系统。 |
| 一个主动作 | 通过 | 只运行一个同用户、同问题的连续内容系列；三篇是同一实验的必要组成，不是三条升级战线。 |
| 可观察指标 | 通过 | 重复用户、问题复述、后续消费行为都能观察，并优先与账号自身基线比较。 |
| 维护成本 | 通过 | 明说会牺牲选题广度和热点点击，并限制数据维护和标题测试。 |
| 版本失效条件 | 通过 | 两轮有曝光但无回访会转向其他原因；样本不足时不做伪结论。 |

**场景判定：通过。** 回答没有把“稳定用户”偷换成粉丝总量，也没有继续强化标题；它把测试对象收敛为“用户是否因连续价值而回来”。

## 场景三：不要玩梗，专业分析职业能力为何难被市场识别

### 输入

> 不要玩梗，请专业分析：一个人的职业能力为什么很难被市场识别？

### 模拟回答

【创作型操作系统｜非本人｜薄肌理论2.0为项目推演】

## 结论

主系统是职业发展。职业能力难被市场识别，通常不是单一的“能力不够”，而是能力、证据、市场语言和信任渠道之间发生了断裂。市场无法直接观察一个人的全部能力，只能根据有限证据判断：这个人能否在特定约束下，稳定解决某类问题，且验证成本是否足够低。

常见有五个原因：

1. **能力嵌在组织环境里。** 成果依赖原公司的品牌、数据、权限、团队和流程，外部无法判断个人贡献，也无法确认换环境后能否复现。
2. **只有结果，没有关键判断。** 简历写了项目和数字，却没有呈现困难约束、本人做出的关键选择、替代方案与因果证据，市场看不出能力是怎样产生结果的。
3. **证据不符合目标市场的识别方式。** 自己使用内部术语或职责清单，而招聘方、客户或合作方按问题类型、业务结果、风险和角色边界来判断价值。
4. **验证成本过高。** 没有作品、案例、推荐、试做或可追问的过程记录，对方需要投入太多时间才能确认能力，往往会选择证据更清楚的人。
5. **需求或渠道不匹配。** 能力真实存在，但目标市场当前不稀缺、预算不足，或证据没有到达真正有决策权的人。这时继续优化表达不会自动创造需求。

## 当前最值得先做的动作

为一个明确的目标角色或客户问题，制作一份可验证案例。只选一个最能代表你的项目，用“问题与约束—你的关键判断—采取的行动—可核验结果—可迁移部分”五段呈现，并尽可能附上经过授权的数据、作品或第三方反馈。目标不是做完整作品集，而是先降低一个关键能力的验证成本。

## 可观察指标

- 找 3 名熟悉目标岗位但不了解该项目的人阅读后，请他们分别复述“你擅长解决什么问题”和“哪项证据最可信”；答案是否一致。
- 后续沟通中，对方是否围绕你的关键判断和结果继续追问，而不是仍只问职责范围。
- 在相近投递或获客渠道中，这份案例带来的有效回复或下一步沟通比例是否高于原材料。

## 维护成本

案例制作需要整理证据、处理保密信息并针对一个目标市场取舍内容；它不会是一份适用于所有岗位的通用材料。先限制在一个案例、一个目标角色，并在目标或证据变化时更新，避免把证明能力本身变成长期高负担项目。

## 版本失效条件

如果目标读者已经能够准确识别能力、也认可证据，但机会仍然没有增加，主要问题就可能是市场需求、价格、地域、渠道或信任关系，而不是能力表达；此时应停止继续润色案例。若关键成果无法获得授权或无法区分个人贡献，也需要改用试做、公开作品或第三方推荐作为验证方式。目标角色变化时，这份案例的选择和语言也必须重做。

### 评估

| 检查项 | 判定 | 依据 |
|---|---|---|
| 个人专业指导 | 通过 | 先给一般机制，再给可由个人执行的证据化动作；没有把一般问题伪装成已掌握用户履历。 |
| 一个主系统 | 通过 | 明确只分析职业发展。 |
| 一个主动作 | 通过 | 只制作一份面向一个目标角色的可验证案例。 |
| 可观察指标 | 通过 | 第三方复述一致性、后续追问方向、有效回复比例均可验证。 |
| 维护成本 | 通过 | 明说证据整理、保密处理、受众取舍和更新负担，并限制范围。 |
| 版本失效条件 | 通过 | 能力已被识别但机会未增加、证据不可授权、目标角色变化都会切换判断或手段。 |
| 严肃模式 | 通过 | 固定归属标签之后，正文完全使用能力、证据、验证成本、反馈与市场条件等专业语言；没有使用体型、肌肉、脂肪、减脂或发力等隐喻，没有笑点和玩梗式收尾。 |

**场景判定：通过。** 严肃模式不仅停止笑点，也完成了术语翻译；回答仍保留原框架的因果结构、行动、指标和更新条件。

## 总结判定

| 场景 | 结果 |
|---|---|
| 能力强但会议汇报协调耗竭 | 通过 |
| 选题多标题猛但没有稳定用户 | 通过 |
| 严肃分析职业能力为何难被识别 | 通过 |

**总体：通过。** 当前 v2.0 能在三个前向场景中给出针对个人处境的专业指导，稳定选择一个主系统和一个主要动作，提供一到三个可观察指标，显式计算新方案的维护成本，并写出可推翻建议的版本失效条件。用户要求“不玩梗”时，正文可以彻底停止隐喻和笑点，只保留专业分析结构。

## 结构性风险

虽然本次三个实际前向输出都通过，但“维护成本”仍是当前 Skill 最容易漂移的一项：理论正文反复强调维护成本，职业指导问题也要求检查维护身份的成本，可默认输出骨架却没有独立的“维护成本”栏，运行前自检也没有直接询问“新方案本身要付出什么成本”。因此，模型严格套用默认骨架时可能只写要删除的旧负担，却漏掉新方案的启动成本、持续成本和机会成本。

这不构成本轮失败，因为三次前向回答均实际给出并限制了维护成本；但若后续要提升稳定性，最小修订方向应是把“维护成本”加入标准输出契约和运行前自检，而不是增加更多理论说明。
